## データの取得と管理

```tsx
<>
  <SearchForm />  // 入力された値を検索をする
  <DataList />    // データを表示する
</>
```

上のようにデータの取得と表示のコンポーネントがそれぞれ独立している場合の設計を考える。
当アプリにおいては `SearchForm` に入力した名前から `id` を取得し、その `id` を元にデータを取得することとする。

### 求める設計
- それぞれのコンポーネントが独立して動く
  - テスト・Storybookの容易性
- なるべく多くのPropsの受け渡しをしない
- Propsのバケツリレーをしない
- コンポーネントで表示しないデータをそのコンポーネント内で持たない・取得しない
- ロジックとビューを分離する

### 課題
- どのようにしてデータ取得処理を行うか
  - ユーザーのアクションを元にイベントハンドラー内で順に取得処理などを実行する(逐次的凝集)
  - stateの変化を元に取得処理を実行する(機能的凝集?)
- データの取得をどこで行うか
  - `SearchForm`コンポーネントでデータを取得する
  - `SearchForm`コンポーネントで取得した`id`を元に`DataList`コンポーネントでデータを取得する
  - `SearchForm`コンポーネントで入力された値を元に、親コンポーネントでデータを取得して`DataList`コンポーネントに渡す
- 逐一WebAPIへのfetch処理をラップしたcustomHooksに分ける必要があるのか
- store を用意する必要があるか

### 検討事項
> コンポーネントで表示しないデータをそのコンポーネント内で持たない・取得しない

`SearchForm`コンポーネントで表示しないデータは`SearchForm`コンポーネントで持ちたくないが、
> ユーザーのアクションを元にイベントハンドラー内で順に取得処理などを実行する

とは相反する。

> ユーザーのアクションを元にイベントハンドラー内で順に取得処理などを実行する

の場合、コンポーネントと関係のないデータを取得することになる。  
取得したデータを store に set するまでが処理に含まれることになりそう。
```ts
const onSubmit = async (event) => {
  const name = event.//
  const id = await findIdByName(name)

  const dataA = await findDataAById(id)
  setDataAAtom(dataA)

  const dataB = await findDataBDataA(dataA)
  setDataBAtom(dataB)
}
```

> stateの変化を元に取得処理を実行する

に関しては、`useEffect`で state の変化を検知することになりそう。
`urql`に、ある値が変化した時にfetch 処理を行う機能があるのでそれを使うのもあり。


> 逐一WebAPIへのfetch処理をラップしたcustomHooksに分ける必要があるのか

customHooks 内で取得したデータの加工を行なっているので必要。
コンポーネントでデータの加工をしてしまうと冗長になってしまうため。


> store を用意する必要があるか

ものによる。入力内容を元にWebAPIから取得したデータをstoreにセットするのはあり。
入力した内容は不要か？
- react-hook-formでは子コンポーネントで定義してある入力内容を親コンポーネントから取得できる


### 決定
> - それぞれのコンポーネントが独立して動く
>   - テスト・Storybookの容易性

`Presentation`層と`Container`層に分けて、Storybookでは`Presentation`層を表示する。  
コンポーネントのテストは複数のコンポーネントを組み合わせた`Integration Test`になる。

> - なるべく多くのPropsの受け渡しをしない
> - Propsのバケツリレーをしない

状態管理ライブラリとCustomHooksを用いてstoreに定義した変数の取得や変更を行う。  
この際、`Presentation`層ではCustomHooksを用いず、表示する変数をPropsとして受け取り表示するだけに止める。ただし、これにより渡すPropsは増えてしまう。

> - コンポーネントで表示しないデータをそのコンポーネント内で持たない・取得しない

状態管理を親コンポーネントで行うこととする。

~~他の要件と照らし合わせると、これに関しては厳守すべきではないと判断。~~
データの取得に関して、上で挙げたコンポーネントを分割前の状態で表すと次のようになる。つまり、useStateでの状態管理で済む。

```tsx
<>
  <div>
    <input value={data} onChange={async (ev) => {
      const data = await fetchData(ev.target.value)
      setData(data)
    }} />
  </div>
  <div>
    <ul>
      {data.mao(d => (
        <li>{d}</li>
      ))}
    </ul>
  </div>
</>
```

> - ロジックとビューを分離する

ロジックを持たず、 View だけを担当する `Presentation` 層と、ロジックを持つ `Container` 層に分ける。
Storybookでは`Presentation`を表示する。
